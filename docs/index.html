¿Qué es y para qué sirve?

El conector MongoDB permite que el agente de Ruvic acceda a tu base de datos en modo solo lectura: puede consultar colecciones y documentos, pero nunca modificarlos. Una vez configurado, puedes pedirle al agente cosas como:

  • “Cuéntame cuántos clientes hay registrados en Bogotá.”
  • “Muéstrame los últimos 10 pedidos de la colección ventas.”
  • “¿Qué colecciones tiene esta base de datos y cuántos documentos hay en cada una?”

Operaciones soportadas:

Operación Qué hace
db.list_collections Lista las colecciones de la base de datos con su cantidad estimada de documentos
db.read Lee documentos de una colección con un filtro (con límite)
db.count Cuenta documentos que cumplen un filtro
db.stats Estadísticas de una colección: documentos, tamaño e índices
Solo lectura, por diseño El conector nunca invoca operaciones de escritura (insert, update, delete): solo emite comandos de lectura. Además, el usuario dedicado solo tiene el rol read. Hay dos barreras independientes.

Prerrequisitos

  • Una base de datos MongoDB 5.0 o superior (en tu servidor, en la nube — MongoDB Atlas, DocumentDB — o en Docker).
  • Acceso administrativo a la base de datos (rol con permiso para crear usuarios, ej. userAdmin), solo durante la configuración inicial.
  • Acceso de red desde la plataforma Ruvic al servidor de base de datos (host y puerto alcanzables; regla de firewall o lista de IPs permitidas si aplica).
  • Los datos de conexión: host, puerto (por defecto 27017) y nombre de la base de datos.

Configuración en el fabricante

Vas a crear un usuario dedicado de solo lectura para Ruvic. No uses el usuario administrador (root) ni el de tu aplicación: un usuario dedicado permite auditar la actividad del agente y limitar el acceso al mínimo.

  1. Conéctate a la base de datos como administrador.

    Usa mongosh u otra herramienta (MongoDB Compass) con un usuario administrador:

    mongosh "mongodb://TU_HOST:27017" -u admin -p --authenticationDatabase admin
  2. Crea el usuario de solo lectura para Ruvic.

    Elige una contraseña fuerte (mínimo 16 caracteres, generada aleatoriamente) y guárdala: la usarás en el formulario de Ruvic (campo Contraseña). El usuario se crea con el rol read sobre la base de datos que quieras exponer:

    use tu_base_de_datos
db.createUser({
  user: "ruvic_reader",
  pwd: "CAMBIA_ESTA_CONTRASEÑA",
  roles: [{ role: "read", db: "tu_base_de_datos" }]
})
    Nota El rol read aplica automáticamente a todas las colecciones de la base de datos, incluidas las que se creen después. No hace falta repetir ningún GRANT.
  3. Habilita el acceso de red desde Ruvic.

    Si tu MongoDB restringe conexiones por IP (habitual en producción), permite la IP de la plataforma Ruvic:

    • Servidor propio: regla de firewall del sistema operativo para el puerto 27017, y verifica que bindIp en mongod.conf permita conexiones remotas.
    • MongoDB Atlas: agrega la IP en “Network Access → IP Access List”.
    [ Captura: regla de firewall / IP Access List con la IP de Ruvic — reemplazar por assets/img/mongodb-firewall.png ]
  4. Verifica el usuario desde fuera del servidor.

    Desde una máquina distinta al servidor de BD (idealmente con salida de red similar a la de Ruvic):

    mongosh "mongodb://TU_HOST:27017/tu_base_de_datos" -u ruvic_reader -p --authenticationDatabase tu_base_de_datos --eval "db.runCommand({ ping: 1 })"

    Si responde { ok: 1 }, el fabricante quedó listo. Anota estos valores para la siguiente sección: host, puerto, base de datos, usuario y contraseña.

Permisos requeridos

Principio de mínimo privilegio: el usuario de Ruvic solo necesita el rol read. No otorgues readWrite, dbAdmin, userAdmin ni roles de clúster.

Permiso Para qué sirve
read (sobre la base de datos a consultar) Listar colecciones (db.list_collections), leer y contar documentos (db.read, db.count) y obtener estadísticas (db.stats)

Los comandos de metadata que usa el conector (listCollections, collStats, índices) están disponibles para cualquier usuario con rol read sobre la base de datos; no requieren permisos adicionales.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta MongoDB y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Host Hostname o IP del servidor (ej. db.empresa.com)
Puerto 27017 (salvo configuración distinta)
Base de datos Nombre de la base de datos a consultar
Usuario ruvic_reader
Contraseña La contraseña del paso 2. Se guarda cifrada como secreto: la interfaz no volverá a mostrarla
Base de datos de autenticación Opcional. Solo necesaria si el usuario se creó en una base de datos distinta a la que se va a consultar (común en MongoDB Atlas, donde suele ser admin)
Timeout de conexión Opcional; 10 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma se conectará a tu base de datos y confirmará que las credenciales y la red funcionan.

[ Captura: formulario del conector MongoDB en Settings → Conectores — reemplazar por assets/img/mongodb-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa a tu-host:27017/tu_base”. La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: “Lista las colecciones de la base de datos MongoDB y dime cuántos documentos tiene cada una.” El agente debe responder con el listado real de tus colecciones. Si lo hace, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
“Autenticación fallida” o “el usuario no tiene permiso de lectura” Contraseña mal copiada, usuario inexistente, o falta indicar la base de datos de autenticación correcta (campo authSource). Reintenta el paso 2 de la sección 3 y revisa el campo "Base de datos de autenticación" en el formulario.
“No se pudo conectar … (timeout)” La plataforma no alcanza el host/puerto. Revisa el paso 3 (firewall / IP Access List / bindIp) y que el host no sea localhost (debe ser accesible desde Ruvic, no desde tu equipo).
“La colección 'X' no existe” Nombre de colección mal escrito. Verifica con show collections en mongosh, conectado a la base de datos correcta.
El agente lista colecciones pero falla al leer una en particular El usuario fue creado con el rol read sobre una base de datos distinta a la que contiene esa colección. Repite el paso 2 de la sección 3 apuntando a la base de datos correcta.
El conector aparece “Sin configurar” tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa host, puerto, base de datos, usuario y contraseña.

Preguntas frecuentes y notas de seguridad

¿El agente puede modificar o borrar documentos?

No. El conector nunca invoca operaciones de escritura (insert, update, delete) y el usuario ruvic_reader solo tiene el rol read. Hay dos barreras independientes.

¿Dónde queda guardada la contraseña?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarla; solo indica “definida”. Para cambiarla, escribe una nueva en el formulario; para conservarla al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: cambia la contraseña en MongoDB (db.changeUserPassword("ruvic_reader", "...")), actualízala en el formulario del conector y pulsa Probar conexión.

¿Qué hago si la contraseña se compromete?

  1. Cambia la contraseña en MongoDB de inmediato (db.changeUserPassword(...)) o elimina el usuario (db.dropUser("ruvic_reader")).
  2. Revisa la actividad reciente en los logs del servidor o en el Audit Log de Atlas.
  3. Actualiza la nueva contraseña en el formulario del conector.

¿Expiran las credenciales?

Por defecto no (usuario/contraseña de MongoDB no caducan solos). Si tu política exige expiración, gestiónala manualmente rotando la contraseña o el usuario según tu calendario de seguridad.

Buenas prácticas Usa siempre un usuario dedicado y de solo lectura; restringe el acceso por IP; no expongas colecciones con datos sensibles que el agente no necesite; y evita compartir la contraseña por canales no seguros.
